# Manufacturing Sales & Quotation Analytics (SQL + Power BI)

A small end-to-end BI project modelled on the order and quotation work of a sheet-metal manufacturing unit:
a **star schema** in MySQL, **analysis queries**, **DAX measures** and a **Power BI dashboard**.

> **Data note:** all data is **synthetic** (generated by `generate_data.py`, seed 42). Customer names, prices and
> quantities are invented for practice. No real company data is used.

## Business questions answered
- How do monthly revenue, order count and average order value trend?
- Which materials and thicknesses drive revenue?
- Who are the top customers, and how concentrated is revenue?
- What share of quotations converts to orders?
- Is the data accurate? (validation checks on amounts and keys)

## Data model (star schema)
| Table | Type | Grain |
|---|---|---|
| `fact_orders` | Fact | one row per order |
| `fact_quotations` | Fact | one row per quotation |
| `dim_date` | Dimension | one row per day (2026) |
| `dim_customer` | Dimension | one row per customer |
| `dim_product` | Dimension | one row per material + thickness |
| `dim_status` | Dimension | order status |

**Relationships (all many-to-one, single direction):**
`fact_orders[order_date_key]` → `dim_date[date_key]` (active) ·
`fact_orders[customer_id]` → `dim_customer` · `fact_orders[product_id]` → `dim_product` ·
`fact_orders[status_id]` → `dim_status` ·
`fact_quotations[quotation_date_key]` → `dim_date[date_key]` · `fact_quotations[customer_id]` → `dim_customer` ·
`fact_quotations[product_id]` → `dim_product`

## How to run
1. Install MySQL 8.0+. Start the client from this folder: `mysql --local-infile=1 -u root -p`
2. `SOURCE sql/01_schema_and_load.sql;` (creates `sales_analytics` and loads the CSVs)
3. `SOURCE sql/02_analysis_queries.sql;`
4. Power BI Desktop: Get Data > Text/CSV (or MySQL), load the six tables, create the relationships above,
   mark `dim_date` as a date table, then add the measures from `dax/measures.dax`.

## SQL techniques used
Multi-table JOINs · CTEs · window functions (`RANK`, `LAG`, running `SUM() OVER`) · `GROUP BY ... HAVING` ·
subquery · conditional aggregation · data-validation queries · indexes on reporting columns

## DAX techniques used
`CALCULATE` with filter context · `DIVIDE` · `DISTINCTCOUNT` · time intelligence (`DATEADD`, `TOTALYTD`) ·
`ALLSELECTED` / `MAXX` for share-of-total
